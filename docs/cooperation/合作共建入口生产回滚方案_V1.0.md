# 合作共建入口生产回滚方案 V1.0

## 一、目标

异常时优先保护个人信息、COL 唯一性和单一权威数据源，不以“快速切回旧站继续写入”制造双主数据。

```text
rollback_plan_ready = true
rollback_owner_confirmed = false
production_backup_verified = false
rollback_drill_verified = false
rollback_ready = false
```

目标：

- 停止新写入：发现 P0 后 5 分钟内；
- 作出回滚决定：15 分钟内；
- RPO：不超过 15 分钟；
- RTO：不超过 2 小时。

RPO/RTO 是待批准服务目标；没有 PITR/日志备份和真实演练前不得声称已经达到。

## 二、回滚触发条件

出现任一项立即停止扩大流量并进入 P0 处置：

- 登记提交持续失败、成功率低于 99% 或出现 5xx；
- 任意 COL 重复、倒退、复用或记录写入后后台不可见；
- 源/目标记录数量、关键字段或序列无法对齐；
- 未授权人员能够访问后台、管理员 API 或导出；
- MFA、Session 撤销或 RBAC 失效；
- 审计未写入、可被修改/删除或包含敏感明文；
- 数据库连接、备份、恢复点、TLS/证书出现异常；
- 正式域名、HTTPS 或关键路径系统性不可用；
- 隐私告知、授权文本、备案或上线批准被发现缺失；
- 具名发布总指挥、安全负责人或数据负责人要求停止。

## 四、统一回滚流程

```text
发现问题
→ 停止入口与推广
→ 记录最后成功写入时间和 COL
→ 判断故障层（应用 / 身份 / 数据 / 域名）
→ 恢复已验证应用版本
→ 按故障点恢复数据库或保留现库
→ 重新执行安全、数据与业务校验
→ 具名责任人批准恢复
→ 小流量重新发布
```

### 4.1 停止入口

- 首选开启维护/暂停提交开关，公开页可保持只读说明。
- 禁止简单把 DNS 指向仍可写的 Sites。
- 记录停止时间、最后一个成功 COL、数据库事务时间和当前 Deployment ID。

### 4.2 应用回退

- Vercel 方案：Promote 最近一次已验证 Deployment，不删除故障版本。
- 国内容器方案：回退到不可变镜像 tag/digest，并保持数据库写入关闭。
- 环境变量必须与版本成套回退；禁止只回退代码而保留不兼容 schema/Secrets。

### 4.3 数据库恢复决策

| 场景 | 处置 |
|---|---|
| 发布后尚无生产写入 | 恢复切换前快照或清理目标库后重导入 |
| 已有有效新写入、应用故障 | 保留 Production 为权威源，只回退应用 |
| 数据误写/破坏 | 停写，PITR 恢复到故障前时间点，再对账故障窗口增量 |
| COL 冲突 | 停写，保留较大序列，核对全部已发编号，禁止回收号码 |
| 身份/RBAC 故障 | 停用管理员入口和 Session，保留业务数据，修复身份配置 |
| 域名/TLS 故障 | 保持数据库单一写入关闭，通过已验证应急地址只读访问 |

恢复操作不得覆盖唯一的源备份。每次恢复使用副本或新项目演练后再决定是否替换权威库。

## 五、恢复后验证

必须重新执行：

- schema、外键、唯一约束和审计触发器；
- 总量、孤儿、重复 COL、最大 COL 和下一编号；
- `/register`、`/success`、管理员登录和后台读取；
- 普通用户、审核管理员、数据管理员、超级管理员权限矩阵；
- Session 失效和未认证 API；
- 备份/PITR 最新恢复点；
- 域名、TLS、安全响应头和 4xx/5xx；
- 日志中无电话、微信、邮箱、密码、Token 或 TOTP Secret。

## 七、演练与证据

上线前必须在与 Production 同产品、同版本、同备份能力的非生产环境演练：

1. 应用版本回退；
2. 数据库恢复到指定恢复点；
3. 恢复后 COL 与关系校验；
4. 身份/RBAC 配置恢复；
5. 维护页和重新开放；
6. 记录实际停止时间、恢复耗时和数据损失窗口。

Staging 已完成逻辑备份恢复，但没有验证目标 Production 计划、PITR 或生产指挥链，因此当前只能认定回滚方案完成，不能认定 `rollback_ready=true`。
