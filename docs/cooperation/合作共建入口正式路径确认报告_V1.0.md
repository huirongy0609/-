# 合作共建入口正式路径确认报告 V1.0

## 一、结论

正式信息架构路径冻结为：

```text
https://xintuozhiwuye.com/cooperation
├── /register
├── /success
└── /admin
```

```text
path_design_confirmed = true
path_owner_signed = false
production_routes_available = false
main_merge_authorized = false
```

“路径冻结”只表示目标 URL 不再摇摆，不表示这些 URL 已上线或获准部署。

## 二、当前 404 原因

| 路径 | 当前事实 | 原因判断 |
|---|---|---|
| `/` | 正式域名返回 200 | 根域绑定现有 Vercel `judao-club` Production |
| `/cooperation` | 正式域名 404；RC 也为 404 | 当前 RC 缺少合作共建说明/入口页 |
| `/cooperation/register` | 正式域名 404；RC 200 | 合作模块存在于候选分支，但未进入正式生产版本 |
| `/cooperation/success` | 正式域名未发布；RC 200 | 同上 |
| `/cooperation/admin` | 正式域名未发布；RC 未认证 307 | 同上；候选身份链路仅在 Staging 验证 |

404 不是 DNS 解析失败：根域可返回首页，说明请求已到达现有应用。问题在于正式部署版本没有对应路由，以及 RC 本身缺 `/cooperation` 索引页。

## 三、路径语义与访问规则

| 路径 | 用途 | 公开性 | 搜索规则 | 成功条件 |
|---|---|---|---|---|
| `/cooperation` | 合作共建定位、适用对象、合作方向与登记入口 | 公开 | 可索引、canonical 指向自身 | 200；主 CTA 到 `/register` |
| `/cooperation/register` | 公开登记表单 | 公开 | 可索引或按产品决定；canonical 唯一 | 打开、校验、提交、生成 COL |
| `/cooperation/success` | 提交成功确认 | 公开但依赖提交上下文 | `noindex` | 不泄露他人或完整个人信息 |
| `/cooperation/admin` | 管理后台 | 仅授权管理员 | `noindex`、不进 sitemap/导航 | 未认证 302 到登录或 API 401；AAL2 后按 RBAC 200/403 |

管理 API 必须使用服务端身份校验；隐藏链接、前端判断或共享 Basic Auth 均不是合格控制。

## 四、正式集成方式

### 4.1 推荐方式

依据架构路线建议，官网和合作模块应构成同一个 Next.js 构建产物：

```text
同一 Git release commit
→ 同一 CI 与不可变构建
→ 国内 Production 候选
→ 根域全站验收
→ 获批后一次性切换
```

不采用 iframe、临时域名跳转或长期按路径反向代理拼接。应用内部路由直接承载四个正式路径。

### 4.2 `/cooperation` P0 修复

必须新增正式入口页，或明确做同域 308 到 `/cooperation/register`。优先采用说明页 200，以承载平台定位、隐私/授权说明和登记前预期；不能让根路径继续 404。

### 4.3 是否进入 `main`

最终上线版本必须进入 `main`，但 No.030-A 禁止合并。顺序为：

```text
feature 已验证提交
→ staging 等价验证
→ release/cooperation-v1 冻结与评审
→ No.030-C Go 决定
→ 合并 main
→ 发布指定 main commit
```

禁止把未经 review 的 feature 分支直接发布到 Production，也禁止把“已进入 main”当作自动上线许可。

## 五、发布后的访问链路

### 5.1 公开登记

```text
访客打开 /cooperation
→ 阅读合作共建定位与授权说明
→ 进入 /cooperation/register
→ 服务端校验并写入唯一 Production 数据库
→ 原子生成 COL 编号
→ 跳转 /cooperation/success
→ 人工跟进
```

### 5.2 管理访问

```text
管理员访问 /cooperation/admin
→ 登录
→ TOTP MFA / AAL2
→ Session 建立
→ 服务端 RBAC
→ 查看或执行角色允许的操作
→ 追加式审计
```

### 5.3 域名与 canonical

- `xintuozhiwuye.com` 是唯一正式主域；
- `www` 或其他已购域名仅在批准后 301/308 到唯一主域；
- 不允许 Sites、Vercel Preview 或国内云临时域与正式入口同时可写；
- canonical 指向正式主域对应公开页面；`/success`、`/admin` 不参与内容权威竞争。
