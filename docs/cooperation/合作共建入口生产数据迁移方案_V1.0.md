## 三、数据范围

迁移：

- 正式 `cooperation_lead` / 登记记录及机构信息；
- 合作状态历史；
- 原始提交时间、来源页面和授权记录；
- 已发行 COL 编号；
- 年度最大 COL 值。

不迁移：

- Staging 一次性测试用户、管理员映射和测试审计；
- Mock/localStorage、演示数据或未获授权的案例材料；
- 共享口令、Session、TOTP Secret、服务端密钥；
- 无法说明来源或无法通过字段校验的记录，需进入异常清单人工裁决。

## 四、T-24 小时准备

### 4.1 变更冻结

1. 冻结 Release Candidate commit、数据库 schema、依赖锁文件和迁移工具。
2. 禁止新增字段、修改 COL 规则、变更 Auth/RBAC 或调整授权文本。
3. 记录最终候选 Commit、Vercel Deployment、Production 数据库项目 ID 和 Secret 版本。
4. 确认 `/cooperation` 404 已修复并在新的 RC 上重新验收。

### 4.2 数据基线

1. 对 D1 做只读预导出，保存 SHA-256、导出时间和导出人。
2. 统计总行数、有效/异常记录、年份分布、最大 COL、重复 COL、空关键字段。
3. 对最近一次导出后新增记录形成增量清单。
4. 数据负责人确认哪些记录是正式数据；测试/演示记录不得导入。

### 4.3 Production 准备

1. 创建独立 Production 数据库与 Auth 项目，不连接 Staging。
2. 配置备份/PITR、网络限制、TLS、CA、日志与告警。
3. 部署空 schema 并执行约束、索引、触发器检查。
4. 对空库创建切换前快照/逻辑备份，验证可以恢复。
5. 完成 Production 管理员 MFA 与最小权限测试。
6. 准备维护告知和停止提交开关；旧 Sites/D1 不得继续成为第二写入源。

## 五、T-0 执行流程

### 5.1 停写与最终备份

```text
宣布 T-0
→ 旧入口停止新提交
→ 确认在途请求归零
→ D1 最终全量导出
→ 生成 SHA-256
→ Production 切换前备份/快照
```

停写后若 D1 仍出现新增记录，立即 No-Go，先确认写入源和在途请求。

### 5.2 Schema 和导入

1. 从批准的 release artifact 执行版本化 schema migration。
2. 验证六张表、外键、唯一约束、索引、审计不可变触发器。
3. 在受控事务或可回滚批次中导入正式记录。
4. 历史 `source_page` 原值保留；不得批量伪造正式来源。
5. 使用 `GREATEST(现值, 历史最大值)` 续接年度 COL 序列。
6. 导入失败时整体停止，不允许跳过异常后继续切流。

### 5.3 强制校验

| 校验 | 通过条件 |
|---|---|
| 总量 | 源正式记录数 = 目标登记数 |
| 机构关系 | 每条登记均有机构，无孤儿 |
| COL | 0 重复、0 非法格式，目标最大值等于源最大值 |
| 序列 | 下一号 = 历史最大号 + 1，不倒退、不重置 |
| 时间 | 原提交时间保留时区语义 |
| 授权 | 授权字段和值不被扩大解释 |
| 敏感字段 | 电话、微信、邮箱未进入日志或构建产物 |
| 审计 | 导入、校验、操作者、批次号全部留痕 |

任何一项不通过即停止发布并转入回滚。

## 六、T+ 业务验证

在不扩大公开流量前，由具名验收人员完成：

1. 打开 `/cooperation` 与 `/cooperation/register`。
2. 使用真实且已批准的内部验收信息完成一条登记；禁止虚构机构或联系人。
3. 确认提交 HTTP 201、成功页正常、生成下一枚 COL。
4. 审核管理员完成 MFA 后查看该记录并执行允许的状态更新。
5. 数据管理员核对统计/导出权限，审核管理员导出必须被拒绝。
6. 超级管理员查看登录、提交、查看、审核和拒绝的审计事件。
7. 登出后 Session 失效，未认证 API 返回 401。
8. 核对数据库备份/PITR 最新恢复点已覆盖上线后的写入。

验收记录如为真实业务线索可继续保留；如为专门批准的测试记录，应按数据负责人确定的“标记并排除统计”规则处理，不得擅自删除或复用其 COL。

## 七、切流与观察

- 初始只向内部验收人开放，不公开推广。
- 通过 T+ 验证后小范围发送，观察至少 2 小时。
- 24 小时持续监控 4xx/5xx、提交成功率、数据库连接、COL 重复、Auth 错误和审计写入。
- 旧入口保持只读/维护状态，禁止双写。
- 稳定期结束后由发布总指挥确认关闭迁移窗口。

## 八、迁移完成定义

```text
最终源备份有哈希
+ Production 备份可恢复
+ 数据数量和关系一致
+ COL 连续且无重复
+ 真实业务链路通过
+ 管理员与审计通过
+ 观察期无 P0/P1
+ 具名数据负责人签认
= migration_ready = true
```

当前上述 Production 证据均未形成，因此 `migration_ready=false`。
