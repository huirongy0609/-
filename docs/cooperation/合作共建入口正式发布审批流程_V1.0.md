## 三、阶段门

### Gate A：治理基线签认

通过条件：

- 生产路线、正式路径和统一迁移范围已签认；
- 三类管理员及资源责任人具名并由本人接受；
- 数据地域、供应商、备案和个人信息责任边界有书面结论；
- DNS、云账号、数据库、备份、Secrets 和回滚职责明确。

当前状态：`BLOCKED`。

### Gate B：Production 候选验证

通过条件：

- 生产资源已按批准路线建立，但正式入口仍未开放；
- release commit、不可变构建和四路径通过；
- Production Auth/MFA/RBAC/Session/API/审计负向测试通过；
- Production 备份/PITR 与恢复演练通过；
- 依赖安全审计无未处置 high/critical；
- 主站全量回归、国内网络、TLS、监控与告警通过。

当前状态：`NOT STARTED / 未授权创建资源`。

### Gate C：迁移与最终 Go/No-Go

通过条件：

- T-24 冻结、人员、窗口、源导出和回滚材料完备；
- T-0 停写、备份、迁移、schema、数量、关系和 COL 校验通过；
- T+ 登记、COL、后台审核和审计通过；
- 五项状态均为 true：

```text
production_ready = true
migration_ready = true
security_ready = true
admin_ready = true
rollback_ready = true
```

当前状态：`NOT STARTED`。

## 四、正式审批链

```text
技术负责人确认
↓
数据负责人确认
↓
安全/合规负责人确认
↓
合作业务与验收负责人确认
↓
项目总架构师批准
↓
Project Owner 批准业务上线
↓
发布总指挥签发一次性发布授权
↓
执行发布
```

“依次确认”不表示后一角色可以覆盖前一角色的阻断；所有必签项必须同时有效。

## 五、审批证据要求

| 确认人 | 最少证据 |
|---|---|
| 技术负责人 | release SHA、CI/build、Deployment ID、四路径与主站回归、应用回退版本 |
| 数据负责人 | 源/目标数量、导出哈希、最大/下一 COL、备份 ID、恢复报告、异常清单 |
| 安全/合规负责人 | MFA/RBAC/Session/API/审计报告、Secret 双人复核、数据地域与隐私意见 |
| 合作业务负责人 | 正式文案、三类授权、测试登记与人工跟进规则 |
| 验收负责人 | 完整验收矩阵、失败项为零或已拒绝发布 |
| 总架构师 | 架构路线、偏差/例外、风险清单的明确批准 |
| Project Owner | 具名责任人、预算/资源、运营承接和上线窗口批准 |
| 发布总指挥 | Go/No-Go 会议纪要、批准时间、发布窗口、回滚联系人 |

电子签名、企业审批系统记录或可核验会议纪要均可作为证据；仅生成 Markdown、口头转述、空白签名栏或 AI 输出不算批准。

## 七、发布中止与回滚

出现以下任一项立即中止：

- 任一必签人撤回批准或无法到场；
- 构建 SHA/配置与批准版本不一致；
- 备份/PITR 不可用；
- 数据数量、关系或 COL 不一致；
- 未授权访问、越权、MFA/Session/API/审计异常；
- `/cooperation` 四路径或主站关键路径异常；
- DNS、TLS、备案或数据地域条件不满足。

中止后按照《合作共建入口生产回滚方案 V1.0》执行；恢复公开写入必须重新取得数据、安全、技术和发布总指挥批准。
