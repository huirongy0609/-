## 进入 Pre-release Candidate 的必过项

1. 在选定国内云或批准的托管环境创建隔离的 Staging PostgreSQL 与备份策略。
2. 配置三个必要变量并使 `npm run cooperation:staging:check` 通过。
3. 接入组织身份提供方，完成 MFA、账号建档、三角色和禁用测试。
4. 在远程 Staging 重做两轮迁移及恢复演练，并由数据责任人签署。
5. 完成公开提交、COL 生成、后台 302/401/200、权限越权和审计写入测试。
6. 处置生产依赖 high 漏洞，或由安全责任人形成具名风险接受记录。

## 回滚与禁止项复核

- 未改 DNS、未部署生产、未删除历史数据、未重置 COL、未修改 main。
- 数据切换失败时保留 D1 为权威源，停止目标写入并回退路由；任何源数据删除须另行批准。
- 即使后续 `pre_release_ready=true`，也只进入 No.030 正式发布评审，不代表批准生产发布。
