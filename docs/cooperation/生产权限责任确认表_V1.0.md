## 三、职责分离

| 操作 | 申请/发起 | 执行 | 复核/批准 |
|---|---|---|---|
| 新建超级管理员 | Project Owner | 现任超级管理员/身份技术人员 | 安全负责人 + Project Owner |
| 角色变更 | 业务或数据负责人 | 超级管理员 | 安全负责人 |
| 登记审核 | 合作审核管理员 | 合作审核管理员 | 合作业务负责人抽查 |
| 数据导出 | 业务负责人提出用途与范围 | 数据管理员 | 数据负责人/合规负责人 |
| 生产备份恢复 | 数据负责人发起 | 数据管理员/数据库运维 | 安全负责人 + 发布总指挥 |
| 紧急停权 | 安全负责人或发布总指挥 | 超级管理员 | 事后双人复核 |
| 审计查阅 | 安全/合规负责人 | 超级管理员提供只读访问 | Project Owner 按需批准 |

禁止同一人单独完成敏感导出“申请—批准—执行”全链路。超级管理员不得作为日常审核共享账号。

## 四、MFA 与账号要求

- 每人一个具名账号和唯一企业邮箱/经批准身份标识；
- 管理员访问必须达到 AAL2，使用本人独立 TOTP；
- TOTP Secret 不截图、不进入工单、代码库、邮件或聊天；
- 恢复码由本人保管，并在企业密码库中设双人应急控制；
- 登录失败、因子重置、角色变更、导出、Session 撤销必须留审计；
- 离岗或换岗先撤销 Session 和角色，再完成交接；禁止移交原账号密码；
- 至少每季度复核一次权限，临时权限必须有到期时间。
