## 二、生产角色

| 角色 | 核心职责 | 允许权限 | 明确禁止 |
|---|---|---|---|
| 超级管理员 | 最高权限、用户/角色管理、紧急停用、审计查看 | `user:manage`、`role:manage`、`audit:read` 及必要业务权限 | 绕过 MFA、删除/改写审计、共享账号 |
| 合作审核管理员 | 登记查看、审核、合作状态维护 | `lead:read`、`lead:review` | 管理用户/超级管理员、批量导出、改审计 |
| 数据管理员 | 数据导出、统计、备份核对 | `lead:read`、`data:export`、`stats:read` | 修改审核结果、管理角色、删除登记 |

日常操作遵守职责分离：超级管理员不作为常规审核人或导出人；紧急介入必须写明原因和工单号。

## 四、账号建档流程

1. Project Owner 提交具名人员、角色、业务必要性和到期日。
2. 安全负责人核对实名身份、唯一邮箱/企业身份和利益冲突。
3. 超级管理员在 Production Auth 创建个人账号；禁止共享邮箱。
4. 在 `cooperation_admin_user` 建立 `subject_id` 与单一角色映射。
5. 用户本人首次登录并绑定 TOTP；二维码和 Secret 不截图、不转发。
6. 完成 AAL2 后分别执行允许与拒绝场景测试。
7. 审计记录账号创建、角色授予、MFA 成功和测试结果。
8. Project Owner、安全负责人和验收负责人共同确认启用。

## 五、MFA 与恢复材料

- 每人使用独立 TOTP 因子，禁止把短信作为管理员唯一第二因素。
- TOTP Secret 只在绑定时呈现给本人，不进入工单、聊天、截图或代码库。
- 恢复码由本人保存一份；紧急恢复材料放入企业密码库/保险箱，采用双人取用。
- 丢失设备时先停用账号和全部 Session，再由超级管理员与安全负责人双人复核重绑。
- 因子重置、恢复码使用、异常地点登录和连续失败必须产生审计与告警。

## 六、密钥保管

| 密钥 | 保管位置 | 可访问人员 | 轮换要求 |
|---|---|---|---|
| 数据库密码/连接串 | Vercel Sensitive 或国内 KMS | 工程主责 + 应急替补 | 人员离岗、泄露疑似、定期轮换 |
| Supabase 服务端管理密钥 | 独立 Secret；不进入普通应用客户端 | 身份/数据管理员受控流程 | 使用后核对日志；泄露立即吊销 |
| 管理员 TOTP | 用户本人设备 | 仅本人 | 设备丢失立即重绑 |
| 恢复码 | 企业密码库双人控制 | 指定应急人员 | 每次使用后重生成 |
| 备份加密密钥 | KMS/独立保险箱 | 数据主责 + 安全复核 | 与数据库凭证分离轮换 |

禁止把任何 Secret 写入 Markdown、Git、普通邮件或即时通信正文。

## 七、权限交接与离岗

```text
交接申请
→ 接任人具名批准
→ 接任人独立账号与 MFA
→ 最小权限测试
→ 原人员 Session 撤销
→ 原角色映射禁用
→ 密钥/恢复材料轮换
→ 审计和交接单归档
```

离岗或职责终止应先撤权后交接数据；禁止直接把原账号密码交给接任人。临时授权必须设置到期日，到期自动或人工复核撤销。

| 测试 | 通过条件 |

| 普通用户 | 后台/API 401 或 403 |

| 审计 | 授权、拒绝、角色变更、导出和 MFA 事件完整 |
