# 合作共建入口正式路径冻结记录 V1.0

## 一、冻结对象

```text
canonical_production_origin = https://xintuozhiwuye.com
cooperation_root = /cooperation
path_definition_frozen = true
human_path_signoff_complete = false
formal_paths_signed = false
```

目标路径：

```text
https://xintuozhiwuye.com/cooperation
├── /cooperation/register
├── /cooperation/success
└── /cooperation/admin
```

本冻结记录禁止后续工程在未走变更审批的情况下另起正式子域、临时域、iframe 或第二套可写入口。路径定义已形成，但没有真实签认证据，因此 `formal_paths_signed` 仍为 `false`。

## 二、路径契约

| 路径 | 页面职责 | 访问规则 | 索引规则 | 验收响应 |
|---|---|---|---|---|
| `/cooperation` | 合作共建定位、对象、方向、授权提示和登记 CTA | 匿名公开 | 可索引，canonical 指向自身 | 200 |
| `/cooperation/register` | 正式登记表单 | 匿名可读写；服务端校验与限流 | 可索引或按产品签认，canonical 唯一 | GET 200；有效提交 201/成功跳转 |
| `/cooperation/success` | 本次提交结果和 COL 确认 | 不得枚举或读取他人记录 | `noindex` | 正常提交上下文 200；无效上下文安全降级 |
| `/cooperation/admin` | 管理员后台 | 未认证跳登录；AAL2 + RBAC | `noindex`，不进导航/sitemap | 未认证 302；无权 403；有权 200 |

对应管理员 API 未认证必须 401，不得只依赖前端跳转。

## 三、当前 404 原因

- 根域首页返回 200，说明 DNS 和当前正式应用入口可达；
- 正式 Production 部署尚未包含合作模块，因此 `/register` 等正式路径为 404；
- Release Candidate 已有 `/register`、`/success` 和受保护 `/admin`，但缺少 `/cooperation` 根说明页；
- 已验证代码仍在合作候选分支，尚未按审批链进入 release/main 和正式构建。

结论：当前 404 是应用版本/路由缺失，不是根域 DNS 故障。

## 四、正式集成方案

依据 `B_DOMESTIC_CLOUD` 路线：

```text
官网现有 Next.js 代码
+ 合作共建模块
+ /cooperation 说明页
→ 同一 release commit
→ 同一容器镜像
→ 国内云未公开 Production 候选
→ 全站与四路径验收
→ No.030-C Go
→ 合并 main 与批准发布
→ 根域切换
```

实施要求：

- 官网与合作模块同构建、同域、同证书、同发布版本；
- `/cooperation` 必须实现 200 说明页，不再保留 404；
- 不采用长期 iframe、临时域跳转或按路径反向代理拼接；
- Staging/Preview URL 不对外作为正式入口；
- 数据层只有国内 Production 一个正式写入源；
- `main` 仅在 No.030-C 真实 Go 后合并，本任务不授权合并。

## 七、路径变更控制

任何新增、删除、重定向或 canonical 变化必须由产品/业务、技术、SEO/GEO 和总架构师共同评审。以下变化视为重大变更：

- 把正式入口改为子域或第三方域名；
- 把 `/cooperation` 改成永久重定向；
- 让 `/admin` 可索引或进入公众导航；
- 增加第二个可写登记入口；
- 改变成功页的 COL 展示或可查询范围。
