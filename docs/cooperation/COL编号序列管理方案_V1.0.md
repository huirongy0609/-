# COL 编号序列管理方案 V1.0

## 编号定义

格式：`COL-YYYY-NNNN`，含义为 Cooperation Lead（合作共建线索）登记编号。它不代表伙伴身份、案例编号、认证或合作批准。

截至本次受保护导出：

- 当前最大编号：`COL-2026-0001`
- 下一编号：`COL-2026-0002`
- 禁止重新从 0001 起号。

## 生成机制

`cooperation_col_sequence` 以年份为主键。在登记事务内执行原子 UPSERT：首次写入为 1，已有年份将当前值加 1并返回。随后格式化为至少四位数字。

数据库同时对 `lead_number` 建立唯一约束。因此：

- 并发请求由数据库行级并发控制串行化年度序列更新；
- 应用重试不会绕过唯一约束；
- 事务失败会同时回滚序列、机构、登记和初始状态；
- 序号允许因极端运维恢复产生空洞，但禁止复用已发编号。

## 迁移续接

迁移工具按年份解析全部历史 COL，并以 `GREATEST(当前值, 历史最大值)` 更新序列表。正式切换前必须重新检查源库最大值，避免导出后新增记录造成冲突。

## 异常恢复

1. 唯一冲突：中止事务，核对源库与目标库最大号，不得手工改小序列。
2. 序列大于记录最大值：保留较大值并记录审计，不回收号码。
3. 序列小于记录最大值：在受控事务内提升到记录最大值，双人复核。
4. 跨年：新年份自动从 0001 开始，但旧年份序列永久保留。
5. 手工修复需记录操作者、依据、前后值、时间和审批单号。
