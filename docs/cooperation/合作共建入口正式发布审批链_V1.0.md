## 四、签认内容

### 技术负责人

确认指定 release commit、镜像、环境变量名称、路由、监控和回退版本一致；无未处置 P0/P1 技术缺陷。

### 数据负责人

确认源/目标记录、授权、关系、最大/下一 COL 一致；Production 备份和恢复实测满足批准目标；不存在双写。

### 安全合规负责人

确认管理员均为具名个人账号并完成 MFA；RBAC、Session、API、审计、Secrets、数据地域和备案条件有效。

### 业务负责人

确认定位、三类授权、字段、成功页、后台审核与人工跟进可以真实运行，不产生自动伙伴身份、自动认证或自动公开。

### 项目总架构师

确认 B_DOMESTIC_CLOUD、正式路径、云产品组合、技术债关闭和偏差均符合批准基线。

### Project Owner

确认具名责任人、预算/采购、运营承接、发布窗口和剩余风险，签发仅对指定版本和窗口有效的上线授权。

## 五、一次性发布授权约束

发布授权必须绑定：

- release SHA 与镜像 digest；
- Production 资源 ID 与数据库实例；
- 最终导出哈希、迁移批次和下一 COL；
- DNS 变更集、TTL 与回退值；
- 发布窗口和到场责任人；
- 回滚版本、备份/PITR 点和 RTO/RPO；
- 允许变更与禁止变更；
- 批准证据编号。

任一绑定项变化，授权自动失效并重新评审。

## 六、一票阻断条件

- 任何必签责任人未具名、未到场或撤回确认；
- 版本、镜像、配置或资源与批准对象不一致；
- 备份/PITR 无法恢复；
- 记录、授权、关系或 COL 不一致；
- MFA/RBAC/Session/API/审计存在绕过；
- 备案、域名、证书、数据地域或授权条件不成立；
- `/cooperation` 四路径或主站关键路径失败；
- 出现未处置 critical/high 依赖或 P0/P1 缺陷。

阻断后只能宣布 NO-GO 或 ABORT，不得以会议口头同意绕过。
