## 三、OIDC/身份安全

新增候选适配实现：

- OIDC Authorization Code + PKCE S256；
- 随机 `state`、`nonce` 和 verifier，10 分钟临时 Cookie；
- issuer、audience、签名算法、JWKS、时钟偏差和 nonce 校验；
- 必须出现经批准 `acr` 或 `amr` 中的 `mfa/otp/totp`；
- Session Cookie 使用 `__Host-`、HttpOnly、Secure、SameSite=Lax、Path=/；
- IdP `sub` 必须存在于 `cooperation_admin_user` 且角色具备所需权限；
- 成功/拒绝写入审计；
- Staging 继续使用 Supabase，不共享用户或 Secret。

真实 IDaaS 版本、OIDC 应用、MFA 策略、claim 值和 logout/session 撤销尚未配置。阿里云官方说明 IDaaS 支持标准/自研 OIDC 应用和 OTP/TOTP 二次认证，但标准/企业版及增值能力存在计费差异，应在采购前确认。[IDaaS 能力](https://help.aliyun.com/zh/idaas/product-overview/product-overview-2)、[IDaaS 计费与版本](https://help.aliyun.com/zh/idaas/eiam/product-overview/pricing)

## 五、Secrets

已完成变量契约和占位模板，未创建真实 Secret。远程验收必须证明：

- RDS URL、OIDC client secret、后台 Secret 分项保存在 KMS/Secrets；
- Secret 未出现在镜像、Git、构建日志、SLS 或浏览器端；
- 部署角色只能读取指定 Secret；
- 创建、读取、轮换和吊销有审计；
- Staging 与 Candidate 值完全不同；
- 泄露演练能在不重建数据库的情况下轮换。
