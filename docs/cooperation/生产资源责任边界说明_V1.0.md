## 三、DNS 责任边界

### 负责人

- 业务批准：Project Owner；
- 变更申请：发布总指挥或技术负责人；
- 操作执行：具名 DNS 运维；
- 独立复核：安全负责人。

### 操作权限

- 注册商和 DNS 控制台必须开启 MFA；
- 日常子账号不能转移域名、修改实名主体或关闭安全保护；
- DNS 变更前导出当前记录、TTL、证书和回滚值；
- 禁止在无工单、无窗口、无回滚人的情况下直接改根域。

### 审批流程

```text
技术变更单
→ 路径/证书/备案证据确认
→ 技术负责人批准
→ 安全负责人复核
→ Project Owner / 发布总指挥批准窗口
→ DNS 运维执行
→ 双人核对与监控
```

## 四、云平台账号边界

- 云主账号归项目法人/经批准主体所有，主账号凭证进入企业密码库；
- 日常通过具名 IAM/RAM 子账号工作，禁止共享 AccessKey；
- 生产与 Staging 使用不同项目/VPC/账号权限、数据库密码和 KMS Secret；
- 费用、续费、欠费告警必须有具名负责人和替补；
- 删除实例、关闭备份、修改网络边界、导出全量数据属于双人批准操作。

## 五、数据库、备份与恢复

| 事项 | 责任要求 | 验收证据 |
|---|---|---|
| Schema 变更 | 技术负责人提出，DBA 执行，数据负责人批准 | 版本化 migration、review、执行日志 |
| 日常备份 | DBA 监控成功率，数据负责人每周核对 | 备份清单、告警、不可篡改日志 |
| PITR | 按批准的 RPO 配置并持续监控 | 恢复点截图/机器证据、演练报告 |
| 离站备份 | 与主库权限、区域和密钥分离 | 加密对象、哈希、访问审计 |
| 恢复 | 发布总指挥宣布，DBA 执行，数据/安全双复核 | 恢复工单、数据/COL校验、耗时 |
| 数据导出 | 有明确用途、范围、保留期和接收人 | 审批单、审计、销毁/归档证据 |

RPO `≤15 分钟`、RTO `≤2 小时` 延续 No.030 待批准目标；真实 Production 演练前不能声称达标。

## 六、安全配置、MFA 与 Secrets

- DNS、云主账号、管理员后台、数据库控制台和密码库必须使用个人账号与 MFA；
- Production Secret 只能保存在 KMS/Secret Manager/平台 Sensitive Secret，不写入 Git、Markdown、构建日志或聊天；
- Secret 创建、读取、轮换和吊销应留审计，至少由执行人与复核人双人确认；
- Staging Secret 不复制到 Production；Production 数据不回流 Staging；
- 泄露疑似时先吊销/轮换，再调查；不得等待确认泄露后才动作；
- 服务账号使用最小范围和可轮换短期凭证，不以自然人管理员 Token 运行应用。

## 七、故障和恢复指挥

```text
监控/人员发现异常
→ 安全或技术负责人分级
→ 发布总指挥决定停写/回滚
→ 应用、数据库、DNS各责任人执行
→ 数据负责人验证COL与记录
→ 安全负责人验证身份与审计
→ Project Owner批准恢复公开写入
```

任何单一人员不得同时拥有“删库 + 删除备份 + 修改 DNS + 关闭审计”的全套权限。
