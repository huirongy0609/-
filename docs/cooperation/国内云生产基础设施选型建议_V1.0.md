# 国内云生产基础设施选型建议 V1.0

## 一、建议结论

```text
recommended_cloud_provider = ALIBABA_CLOUD
recommendation_status = pending_project_owner_approval
cloud_provider_approved = false
production_resource_creation_authorized = false
```

推荐阿里云作为首选、腾讯云作为合格备选。推荐理由主要是与 No.027/No.028 已形成的阿里云架构方向连续，可减少备案接入、产品映射和运维流程的重新设计，不代表腾讯云在能力上不合格。

最终选择必须等待 Project Owner、总架构师、技术负责人、数据负责人和安全/合规负责人批准，并取得正式报价、账号主体与备案条件核验结果。

## 二、目标能力

候选云必须满足：

- 中国内地可备案计算资源；
- 容器化 Next.js 应用部署、健康检查、灰度/回退与水平扩展；
- 高可用 PostgreSQL、自动备份、日志备份、PITR 和可下载/离站备份；
- CDN、WAF、HTTPS、DDoS 基础防护、访问控制和私网数据库；
- IAM、MFA、KMS/Secret、操作审计、日志和告警；
- 企业实名账号、具名子账号和费用/续费连续性；
- 能在不重置 COL、不双写的前提下从现有数据链路迁移。

## 三、方案 A：阿里云

### 建议产品组合

```text
云解析 DNS
→ CDN / WAF / HTTPS
→ ALB/SLB
→ ECS 上的不可变 Docker 镜像（首期）
→ RDS PostgreSQL 高可用版
→ KMS/Secrets + SLS + CloudMonitor + OSS/DBS 备份
```

首期建议 ECS 容器化部署，而不是把 SAE/ACK 作为备案前提。阿里云官方备案说明明确列出中国内地 ECS 等可备案条件，并提示 ACK/ACS 容器服务本身不能直接申请备案服务码；完成主体和接入核验后，可再评估 SAE 是否作为应用托管层。

| 维度 | 评估 |
|---|---|
| 计算/部署 | ECS + Docker 与当前 Next.js/Node.js 构建兼容性最直观；可用不可变镜像、健康检查和负载均衡，后续可迁 SAE/ACK |
| 扩展 | 从单候选实例扩展到双实例 + ALB；应用无状态化后可水平扩展 |
| 数据库 | RDS PostgreSQL 支持自动/手动备份、日志备份和 PITR；应选择高可用规格并执行真实恢复演练 |
| 网络 | 云解析、CDN、WAF、HTTPS、VPC、安全组、ALB 可组成分层入口；数据库仅私网开放 |
| 安全 | RAM 具名子账号、MFA、KMS/Secrets、SLS 审计和告警可纳入同一企业账号体系 |
| 合规/备案 | 使用中国内地服务器需在实际接入商办理适用 ICP 备案/新增接入；备案主体和云账号主体需提前确认 |
| 企业接受度 | 国内企业常见供应商，便于形成采购、合同、发票和本地主体责任链；仍需项目实际采购审核 |
| 主要风险 | ECS 运维责任高于全托管平台；需明确补丁、镜像、容量、监控和值守责任；备案资源规格需提前核验 |

## 四、方案 B：腾讯云

### 可比产品组合

```text
DNSPod
→ CDN / WAF / HTTPS
→ CLB
→ CVM 上的不可变 Docker 镜像
→ TencentDB for PostgreSQL 高可用版
→ KMS + CLS + 云监控 + COS 备份归档
```

| 维度 | 评估 |
|---|---|
| 计算/部署 | CVM + Docker 可承载同一 Next.js 构建；也可进一步评估 TKE/Serverless，但需单独验证备案与运维边界 |
| 扩展 | CVM/CLB 可从单候选扩展到多实例；需建立镜像、健康检查和自动扩缩策略 |
| 数据库 | TencentDB for PostgreSQL 支持自动/手动全量与日志备份，并可按备份集或时间点恢复；保留策略需按 RPO/RTO 配置 |
| 网络 | CDN、WAF、HTTPS、CLB、VPC、安全组具备完整入口控制；官方给出 CDN→WAF→负载均衡→源站组合 |
| 安全 | CAM、MFA、KMS、CLS 和云审计可形成企业账号边界，需完成最小权限设计 |
| 合规/备案 | 遵循“谁接入谁备案”；使用腾讯云中国境内资源对外服务前需完成适用备案 |
| 企业接受度 | 国内主流企业云供应商，采购与本地支持能力成熟；仍需项目实际采购审核 |
| 主要风险 | 从既有阿里云方向切换会产生产品映射和治理文档重做；备案账号和服务器条件需重新核验 |

## 五、横向比较

| 维度 | 阿里云 | 腾讯云 | 本项目判断 |
|---|---|---|---|
| Next.js 计算 | ECS/SAE/ACK 可选 | CVM/TKE/Serverless 可选 | 首期均建议 VM + Docker，降低平台特性耦合 |
| 水平扩展 | ALB/SLB + 多实例 | CLB + 多实例 | 均满足，需实测健康检查与回退 |
| PostgreSQL | RDS PostgreSQL | TencentDB PostgreSQL | 均具备备份/PITR路线，必须以真实恢复演练验收 |
| CDN/WAF/HTTPS | 完整产品组合 | 完整产品组合 | 均满足 |
| IAM/KMS/日志 | RAM/KMS/SLS | CAM/KMS/CLS | 均满足，取决于责任人和配置质量 |
| ICP 接入 | 中国内地资源在阿里云办理/接入 | “谁接入谁备案” | 均需前置核验，不能先切 DNS 后补 |
| 既有文档连续性 | 高 | 中 | 阿里云优先 |
| 迁移工作量 | 较低 | 略高 | 阿里云优先 |
| 供应商锁定控制 | 需标准 PostgreSQL/容器/导出 | 同左 | 无显著差异 |
| 最终成本 | 待正式询价 | 待正式询价 | 当前不得凭公开单价做最终采购决定 |

## 六、推荐基础配置边界

以下是 No.030-B 的选型边界，不是采购订单：

| 层 | 最低生产候选要求 |
|---|---|
| 地域 | 中国内地，最终地域由备案主体、用户分布和灾备策略批准 |
| 计算 | Docker 化 Next.js；不可变镜像；至少准备双实例/快速替换方案；Node.js 版本与 RC 一致或经兼容验证 |
| 负载均衡 | HTTPS 终止、健康检查、连接排空、回退目标明确 |
| 数据库 | PostgreSQL 高可用；私网；TLS；自动全量 + 日志/PITR；恢复到新实例演练 |
| 存储/备份 | 加密；与主库权限分离；备份哈希/清单；离站或跨地域副本经批准 |
| 身份 | 具名个人账号、MFA、RBAC、Session 撤销、操作审计 |
| WAF/CDN | 上线前规则基线、误拦截回退、缓存不得覆盖动态提交/管理接口 |
| Secrets | KMS/Secret Manager；生产与 Staging 分离；双人复核与轮换 |
| 可观测性 | 访问、应用、数据库、身份和审计日志；5xx、提交失败、COL冲突、越权告警 |
| 恢复目标 | 待批准目标 RPO ≤ 15 分钟、RTO ≤ 2 小时；实测前不标记达成 |

## 七、正式选型前必须补齐

1. 项目/企业主体、云账号实名主体与域名备案主体确认；
2. 当前 `xintuozhiwuye.com` 备案状态、接入商和新增接入要求核验；
3. 阿里云与腾讯云同口径正式报价和三年 TCO；
4. Node.js 24/Next.js 15 容器基准、构建、冷启动和容量测试；
5. RDS/TencentDB PostgreSQL 版本、扩展、字符集、TLS、备份、PITR 和下载能力验证；
6. 身份方案选择及 TOTP/RBAC/审计等价性验证；
7. 运维值守、补丁、续费、欠费、故障升级和供应商支持 SLA；
8. 数据/合规负责人对个人信息、日志、备份地域和保留期签认。

## 八、推荐决定与替代条件

```text
recommended_cloud_provider = ALIBABA_CLOUD
recommended_initial_compute = ECS_DOCKER_PLUS_ALB
recommended_database = RDS_POSTGRESQL_HA
fallback_provider = TENCENT_CLOUD
```

若正式询价、备案核验、技术 PoC 或企业采购政策显示腾讯云明显更合适，可在资源创建前切换为腾讯云，但必须更新架构决策、产品映射、迁移/回滚方案和责任边界，不得在两个云建立同时可写的 Production。
