# 环境隔离设计报告 V1.0

## 一、结论

```text
environment_isolation_design_ready = true
staging_isolated_in_design = true
candidate_isolated_in_remote_evidence = false
```

Staging 不得升级或改名为 Production Candidate。国内候选必须从独立资源重新建立，并使用合成/脱敏数据验证。

## 二、隔离矩阵

| 控制面 | Staging | 国内 Production Candidate | 强制规则 |
|---|---|---|---|
| 应用平台 | Vercel Preview | 阿里云 ECS + Docker + ALB | 不 Promote Staging Deployment |
| 数据库 | Supabase Staging PostgreSQL | 独立 RDS PostgreSQL | 不共库、不跨环境账号、不复制真实数据 |
| 身份 | Supabase Auth | 阿里云 IDaaS/OIDC | 不共用户、Session、TOTP 或 client secret |
| Secrets | Vercel Preview Secrets | KMS/Secret Manager | 不复制值，只复制变量契约 |
| 网络 | Vercel/Supabase 网络 | 独立 VPC/vSwitch/安全组 | RDS 不暴露公网 |
| 域名 | Vercel Preview URL | 独立非正式候选主机名/内网地址 | 禁止绑定 `xintuozhiwuye.com` |
| 数据 | 测试数据 | 合成或批准脱敏数据 | 禁止真实生产 D1 导入 |
| 管理员 | 一次性 Staging 测试身份 | 候选测试身份 | 禁止创建正式业务账号 |
| 日志 | Vercel/Supabase 日志 | 独立 SLS Project/LogStore | 日志不跨环境聚合个人数据 |
| 备份 | Staging 逻辑备份 | RDS/PITR/候选恢复副本 | 互不覆盖、互不恢复 |
| 发布 | feature/staging | release 候选镜像 | SHA/digest 固定，禁止 main |
| 费用 | 现有 Staging 账户 | 独立阿里云预算/告警 | 责任人与续费边界独立 |

## 三、账号与权限隔离

- 阿里云主账号归经批准主体，不与个人 Staging 账号共用；
- Candidate 使用 `candidate-deployer`、`candidate-dba`、`candidate-security`、`candidate-auditor` 等具名 RAM 角色；
- CI 只获得 ACR push 和受限部署权限，不得读取数据库业务数据；
- KMS Secret 按应用、数据库、OIDC 分项授权；
- Staging 管理员无法访问候选 RDS、KMS、SLS 和 IDaaS；
- Candidate 人员无法导出 Supabase Staging Secret；
- 所有权限设置到期日，并在 No.030-C 前复核。

## 四、数据隔离

候选允许：

- 自动化生成的虚构测试机构和测试联系人；
- 与真实个人不可逆关联的脱敏样本，但必须有数据负责人批准；
- 独立测试 COL，例如固定未来年份 `2099`，不得进入正式序列资产。

候选禁止：

- 历史 Sites D1 正式记录；
- 真实电话、微信、邮箱或未经授权的机构资料；
- Production 导出或备份副本；
- Staging TOTP Secret、Session、管理员映射；
- 将合成测试 COL 当作正式编号。

## 五、配置隔离

`deploy/alicloud/production-candidate/environment.example` 只定义变量名和占位符。实际值必须从 KMS/Secrets 注入。

静态准入检查要求：

- `COOPERATION_IDENTITY_PROVIDER=oidc`；
- 数据库为 PostgreSQL 且不能指向 localhost/Supabase；
- 数据库 TLS 不得禁用；
- OIDC issuer、authorization、token、JWKS 和站点地址均为 HTTPS；
- MFA ACR 配置不能为空；
- 不允许 `change-me`、`example`、`placeholder`、`todo` 或 `tbd` 作为真实值。

该检查仅证明配置形态，不证明 Secret 真实、安全或远程服务可用。

## 六、发布与回滚隔离

```text
feature
→ Staging（Vercel/Supabase）
→ release commit
→ ACR immutable image
→ 国内 Candidate（不公开、不绑定正式域）
→ No.030-C
→ main / 正式发布（另行授权）
```

- Candidate 不得回写 Staging 数据库；
- Candidate 回滚只使用自己的镜像与 RDS 备份；
- 正式环境未来创建时仍需与 Candidate 隔离，不得简单把候选 RDS 改名为 Production，除非 No.030-C 明确批准其资源转正且完成全部安全/数据清理证据；
- 本任务默认候选资源不可直接转正。

## 七、销毁与保留

- 合成数据在验证结束后按批准周期清理；
- 审计、构建 digest、恢复报告和费用记录按治理要求保留；
- 候选资源停用需先导出证据，不得删除真实生产数据（候选本就不应包含）；
- 费用责任人必须设置到期提醒，避免遗留计费资源。
