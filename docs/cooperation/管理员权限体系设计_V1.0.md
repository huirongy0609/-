# 合作入口管理员权限体系设计 V1.0

## 角色与最小权限

| 角色 | 允许 | 禁止 |
|---|---|---|
| 超级管理员 | 用户管理、权限管理、审计查看；兼具登记与数据权限 | 绕过 MFA、删除审计日志 |
| 合作审核管理员 | 查看登记、更新审核状态和审核结果 | 用户/权限管理、批量导出 |
| 数据管理员 | 数据导出、统计、只读查看登记 | 修改审核结果、用户管理 |

权限码分别为 `user:manage`、`role:manage`、`audit:read`、`lead:read`、`lead:review`、`data:export`、`stats:read`。服务端逐接口校验，前端隐藏按钮不能作为授权依据。

## 身份、MFA 与登录保护

- 使用组织 OIDC/SAML 身份提供方；禁止共享口令和前端 Bearer 管理口令。
- 身份提供方强制 MFA，服务端会话必须携带 `mfa=true`、主体、邮箱、角色和过期时间。
- 会话使用至少 32 字节密钥签名，Cookie 应设 `HttpOnly`、`Secure`、`SameSite=Lax`、短有效期。
- 登录入口启用失败次数限制、异常地点/设备告警和管理员停用能力。
- 角色由平台管理员在 `cooperation_admin_user` 建档后映射，身份提供方登录成功不等于获得业务权限。

## Admin 访问控制说明

目标行为：

| 请求 | 预期 |
|---|---|
| 未认证访问 `/cooperation/admin` | `302` 至 `/cooperation/admin/login` |
| 未认证访问 `/api/cooperation-leads` | `401` |
| 身份配置缺失的 API | `503`，默认关闭 |
| 已认证、MFA 完成、有 `lead:read` | 页面/API `200` |
| 已认证但无权限 | API `401/403`（实现完善时区分 403） |

当前代码已实现服务端签名会话验证、MFA 声明和 RBAC 判断，并移除浏览器共享口令输入。真实身份提供方、Cookie 签发回调、用户建档与远程环境密钥尚未开通，因此只能认定 `admin_security_defined = true`，不能认定后台登录链路已完成。

## 审计日志

下列事件必须写 `cooperation_audit_log`：登录成功/失败、MFA 失败、查看列表、查看详情、状态变更、导出、角色变更、账号停用、COL 人工修复。日志不保存明文电话、邮箱、微信或会话密钥；IP 仅保存加盐哈希。在线留存至少 180 天，归档期限由数据责任人批准。
