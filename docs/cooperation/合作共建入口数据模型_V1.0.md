# 合作共建入口数据模型 V1.0

## 结论

预发布和生产目标数据层为 PostgreSQL 兼容数据库；SQLite 已从合作模块运行路径移除。本任务提供可执行 schema，未创建远程数据库实例。

## 表模型

| 表 | 用途 | 主键/唯一约束 | 关键关系 |
|---|---|---|---|
| `cooperation_organization` | 机构主体 | UUID | 一对多关联登记 |
| `cooperation_registration` | 用户提交的合作登记 | UUID；`lead_number` 唯一 | 必须关联机构 |
| `cooperation_partner_status` | 伙伴审核状态历史 | UUID | 关联登记；只追加状态事件 |
| `cooperation_col_sequence` | 每年 COL 当前最大值 | `sequence_year` | 事务内原子递增 |
| `cooperation_admin_user` | 管理员主体与角色映射 | 身份提供方 `subject_id`；邮箱唯一 | 角色三选一 |
| `cooperation_audit_log` | 管理操作审计 | UUID | 记录主体、动作、资源、结果 |

SQL 基线：`db/cooperation/001_initial.sql`。

## 数据边界

- 公开提交只写机构、登记和初始 `lead_received` 状态。
- 登记不会自动产生伙伴身份、认证、案例公开或合作批准。
- 联系方式属于受限个人信息，不进入日志、前端埋点或版本库。
- 后台读取必须通过 `lead:read` 权限；导出另需 `data:export`。
- 状态历史采用追加记录，禁止覆盖既有审核事实。

## 一致性与事务

一次登记在单事务内完成：锁定/递增年度 COL 序列、创建机构、创建登记、写入初始状态。任一步失败即整体回滚。数据库唯一约束作为防重复的最终防线。

## 环境要求

| 变量 | 要求 |
|---|---|
| `COOPERATION_DATABASE_URL` | `postgres://` 或 `postgresql://`；仅服务端可见 |
| `COOPERATION_DATABASE_SSL` | 云环境保持证书校验；仅本地可设 `disable` |
| `COOPERATION_DATABASE_POOL_SIZE` | Serverless 场景建议 3–5，并使用托管连接池 |

远程 Staging 应与生产使用同一数据库产品、主版本、扩展和 schema migration；数据库、账号和备份策略未实际开通前，`database_ready` 不得为 true。
